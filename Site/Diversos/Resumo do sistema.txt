🔗 1. Origem das fotos (DSLRBooth / LumaBooth)
Cada serviço gera um link externo do tipo:
https://fotoshare.co/e/qVxJWTc5CXQUIceviSb3r

Plataforma 360 → sempre 2 links (vídeo + paparazzi digital).

Esses links nunca aparecem “crus” para o convidado.

👉 No PhotoMusic Pro, esses links vão ficar guardados em:

pm_event_services → campo pasta_protegida ou um novo campo link_origem.

🧱 2. Camada de proteção (frame / proxy)
O convidado nunca vê o link real da foto/vídeo.

Fluxo:

Ele recebe um link do PhotoMusic Pro, algo como:
https://photomusic.com.br/galeria/evento-123/servico-abc/

Essa página:

mostra o formulário + termo

valida cadastro / aceite

só depois disso carrega o conteúdo do fotoshare dentro de:

um <iframe>

ou redirecionamento controlado

ou proxy interno

👉 A lógica de proteção está no seu sistema, não no fotoshare.

📝 3. Formulário + Termo + Aceite
Primeiro acesso do convidado:

Preenche:

nome

email

telefone (ou capturado automaticamente via WhatsApp em outro fluxo)

Aceita o termo.

O sistema registra em:

pm_convites / pm_aceites / pm_acessos_galeria  
(você já tem essas tabelas prontas)

Dados armazenados:

nome, telefone, email

IP

navegador, dispositivo, user_agent

país, estado, cidade (se disponível)

data/hora do aceite

evento + serviço

👉 Isso você já começou a fazer — só vamos amarrar com o Módulo 5.

🔐 4. Restrição por dispositivo + limite diário
Regras que você definiu:

O link só abre no celular que aceitou o termo:

isso é feito via device_hash + token_acesso em pm_acessos_galeria.

Se a pessoa mandar o link pra outra:

a outra cai no fluxo de termo + cadastro.

Quem já aceitou:

sistema verifica se já existe registro para aquele evento/serviço + device

se sim → libera direto, sem novo formulário.

Limite:

até 10 acessos por dia por pessoa.

Link ativo:

até admin ou usuário desativar.

👉 Tudo isso encaixa perfeitamente na tabela pm_acessos_galeria que você já tem.

🧑‍💼 5. Link do contratante
Contratante recebe um link especial:

pode abrir no computador

não expira

Mas:

também precisa aceitar termo (por segurança jurídica sua e dele).

Esse link é diferente do link do convidado:

outro endpoint

outras regras

outro tipo de registro de acesso.

👉 Isso conversa com:

pm_aceite_contratante

pm_painel_contratante

pm_eventos + pm_event_services.

📜 6. Contratos e eventos
Eventos vinculados a contratos.

Mas:

pode existir evento sem contrato (casos informais, urgentes, etc.).

Admin e usuários com permissão:

podem gerar contrato

podem criar evento sem contrato

podem vincular depois.

👉 Isso conversa com:

pm_eventos

pm_contratos (quando existir)

pm_pagamentos (depois).
